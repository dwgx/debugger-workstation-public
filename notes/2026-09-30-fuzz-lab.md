# After-action — fuzz-lab (D11)

## Mission

Nine labs covered eleven capability domains. D11 (fuzzing) had **no tool, no harness and
no target** — it was the only empty one. There is no AFL on this box and installing a large
binary toolchain was not required, so the decision made deliberately: build a
**self-contained mutation fuzzer in Node with a differential oracle**, pointed at this
repository's own parsers.

The teachable thing is not "feed bytes to a tool". It is the discipline that an input
parser must survive hostile input **without hanging, over-reading, or throwing something
uncaught** — which is exactly what an analyst needs when reversing someone else's format
parser, practised safely against our own code.

## Findings — four real defects in this repository, all fixed

1. **`forensics-lab/tools/triage.mjs: parsePrefetch` over-read.** The guard was
   `b.length < 16`; the parser then read a u32 at offset **72** and a u64 at **76**. A
   20-byte file with the right magic died in `readUInt32LE` with `ERR_OUT_OF_RANGE`.
   `Math.min(n, 64)` capped the *count* but not the *file*. Found as `uncaught`, fixed by
   deriving the bounds from the record layout and **reporting** truncation instead of
   throwing — which is the rule the rest of that file already followed. All 7 real fixture
   records parse identically; forensics-lab's own 37-assertion loop still closes.

2. **`crypto-lab/tools/analyze.mjs: EMAIL_VALUE_RE` is quadratic.** A JWT payload is
   attacker-controlled text. Measured: 50 k → 0.7 s, 100 k → 3.6 s, 200 k → 15.8 s,
   **400 k → 54 s**. Clean n². The analyzer whose job is telling you a token is suspicious
   was the thing that hung, and it hung *silently* — no exception, no output. Found as a
   `hang`. Fixed by anchoring the local part to a non-atom character and bounding every
   run: 400 k is now 11 ms, matched address set unchanged.

3. **`web-reverse/static/lib/triage.mjs: residuals.tableAccessorCalls` is quadratic.**
   `[_$\w]+` and the `\w` reachable past the group are ambiguous. A 300 KB identifier run
   took the function **22 s**. Fixed by anchoring the identifier start: 300 k is now 1 ms,
   match counts identical on a fixed set and on a real obfuscated artifact.

4. **`web-reverse/static/lib/triage.mjs: TRANSPILER_HINTS[nullish-lowering]` is
   quadratic** — *and this is the one that justifies the lab.* Three unbounded `\w+` runs
   with literals between them; a 200 KB run took `triage()` **8.7 s**. It sits in a
   different function in the same file as finding 3, is on no list, and was found only
   because the fuzzer appends 400 000 copies of a random character and waits to see
   whether anything comes back. Findings 2 and 3 you can find by staring at a regex. This
   one you find by running the tool on a file you did not write. Fixed by bounding each
   run to 64 characters; 200 k is now 18 ms, 1.6 MB is 145 ms.

The neighbouring `optional-chining-lowering` hint has the same shape and was **left
alone** — its first branch is anchored on a literal `===`, so it never enters the
quadratic path (measured 0 ms on the same input). Not every regex that looks dangerous
is, and the fix was driven by measurement rather than by pattern-matching on shape.

## What the negative control is for

Each target has a deliberately flawed twin: the same parser with one guard removed. The
loop **fails any run in which a twin survives**, because a fuzzer that cannot catch a
parser with no bounds checks has not demonstrated it can catch anything — and a green run
that means nothing is worse than a red one.

The pcap twin shows why a differential oracle beats a crash counter. Its defect is
*silent*: it `subarray`s `incl_len` unchecked, and `Buffer.subarray` clamps, so it returns
a 4-byte frame while **reporting 1000**. Nothing throws. An analyst reading that report
would believe they had a kilobyte of captured traffic. A crash-counting fuzzer sees
nothing there.

The control earned its place immediately. An early run reported
`web-triage: the flawed twin SURVIVED` — and the cause was **the mutator**, not the
parser: `textRepeat` topped out at 60 000 characters, below the 4 s ceiling for a quadratic
regex, so the flaw was genuinely unreachable. That is a false negative that reads exactly
like a real one. The fix was to widen the strategy until the flaw is reachable, not to
weaken the assertion.

## What the next agent should do differently

- **Delta-debugging a hang is unstable; record it un-reduced.** Removing bytes makes a
  *threshold* measurement unstable — a case at 4.01 s during the predicate call returns at
  3.98 s during verification, with no change to the input. Five of 61 triages failed this
  way and nothing was wrong. A hang *near the ceiling* is inherently marginal, so it is
  recorded un-reduced with the reduced size and the reason in the note, and `MARGINAL` in
  the transcript. Do not loosen the check to make this go away: a smaller case that does not
  replay is worse than a larger one that does. An `uncaught` is deterministic and never
  takes this path.
- **Bound the triage sample and print both numbers.** Triaging all 43 findings took 26
  minutes, almost all of it re-minimising variants of the same `RangeError`. Capped at 3
  per target/variant/outcome class. The finding COUNT is complete; only the reduction work
  is sampled, and the loop prints both so the sample is never read as the total.
- **The "at least one reference finding" assertion had to invert.** It originally demanded
  a live defect in a reference parser — which would have meant the lab could only pass while
  a bug was still present, i.e. it would have *rewarded* being broken. It now accepts either
  a live finding, or no live finding with every known defect under guard and holding, and
  rejects the empty middle, which is indistinguishable from a fuzzer that finds nothing.
- **Treat a hang as a finding, not a skip.** Three of the four defects were hangs. None of
  them threw, and a fuzzer that skips timeouts reports all three as clean. This is the
  single highest-value thing in the lab.
- **Read the loop's own failures first.** Every harness bug found during this build
  surfaced as a *red* run, not a silent pass, and three of them were the recipe machinery
  producing wrong bytes that still looked plausible:
  1. the strategy-**selection** draw was not replayed (58/58 triages hash-mismatched);
  2. the step-**count** draw was drawn by the caller, so the replay never consumed it;
  3. the alphabet was recorded as a *size* and rebuilt as `0..n-1` (122/800 mismatched).

  `replayRecipe` now replays all three draws and **checks** the recorded name against what
  the stream picks, so pool drift throws instead of returning plausible wrong bytes.
  2400/2400 round-trips reproduce exactly.
- **Do not add a corpus seed without checking the generator is deterministic.** The first
  draft seeded from `web-reverse/static/gen-obf.mjs`, which produces the most structurally
  meaningful web input available. It is not byte-deterministic —
  javascript-obfuscator draws from an internal RNG that `--seed` does not reach (measured:
  `signer-obf.js` `877ac287…` vs `6672d330…` for the same seed). `assertDeterministic`
  caught it. The committed JS sources are the better seed anyway: 39 KB of real ESM
  exercises the line/byte heuristic, the transpiler hints and the residual regexes far
  harder than a 4 KB minified file does.
- **One process per input is the price of a real ceiling.** A regex backtracking through a
  400 KB claim never yields to the event loop, so nothing inside the process can stop it;
  the parent has to kill. Do not "optimise" this into an in-process loop with a deadline —
  that is how findings 2, 3 and 4 become invisible again. `worker.mjs` deliberately has no
  self-abort timer: it could not fire during a synchronous hang, so it would have looked
  like a safety net while being dead code.
- **Minimise against the real subprocess, not a cheaper predicate.** The ReDoS findings
  reproduce at 4 s and not at 40 s; an in-process minimiser would reduce to a case that
  only misbehaves in-process.
- **The `pcap` reader was written for the fuzzer.** The station had a pcap *writer* and no
  JS reader (net-reverse shells out to tshark, and a third-party dissector is not a target
  this repo may claim). Its findings are real, but "we fuzzed our pcap reader" means
  something different from "we fuzzed a reader we had been running for a year". The three
  unpredicted findings are all in the *pre-existing* targets.
- **Passing tool flags through the wrapper:** `-NodeArgs '<flags>'` or first-class params.
  Bare `--flags` are eaten by the PowerShell binder, same as documented for
  `web-reverse-lab.ps1` and `crypto-lab.ps1`.
- **Reproducer bytes are gitignored on purpose.** A reproducer is hostile input against
  the parsers this repo ships; committing it would put the thing that breaks those parsers
  next to the parsers. The *recipe* is the committed form, and `tools/replay.mjs`
  re-derives the bytes and checks the hash.

## Limits, stated in `fuzz-lab/README.md` and not softened here

No coverage guidance (no instrumentation, no feedback loop), no native or C targets (no
ASAN/UBSAN — a 1-byte out-of-bounds read inside a Buffer is invisible to this engine), no
AFL features at all, one process per input (≈2N spawns per target), and a 27-seed corpus
that caps reach. This is **mutation fuzzing with a differential oracle, not a
state-of-the-art fuzzer**, and the compensating advantage is that `node tools/loop.mjs` is
the whole install.

A `rejected` outcome is also not a correctness claim: the lab proves the parser returned a
*decision*, not that the decision was right. Catching "rejects everything" needs a
differential oracle over answers, which is a different tool.
